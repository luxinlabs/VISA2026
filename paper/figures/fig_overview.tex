\textbf{Task} (\texttt{bias\_add\_col}): $\mathit{out}[i,j]=x[i,j]+b[i]$, \texttt{@main(\%x: tensor<4x2xf32>, \%b: tensor<4xf32>)}.\\[2pt]
\textbf{Fact MOD.SYN.3, prose (B):} ``One-dimensional integer-list attributes (dimensions, permutation, \ldots) are written like \texttt{array<i64: 0, 1>}, never in the older \texttt{dense<[0, 1]> : tensor<2xi64>} form; \ldots''\\[2pt]
\textbf{Same fact, structured (C):} \texttt{\{"id":"MOD.SYN.3","rule":"int\_list\_attr := `array<i64: d0, d1, ...>` (NOT `dense<[...]> : tensor<Nxi64>`); \ldots; example: `array<i64: 0, 1>`"\}}\\[2pt]
\textbf{Agent} (mini, D$^+$: this rule shown upfront), first attempt:\\
\texttt{\%0 = "stablehlo.broadcast\_in\_dim"(\%b) \{broadcast\_dimensions = \textbf{dense<0> : tensor<1xi64>}\} \ldots}\\[2pt]
\textbf{Verifier:} \texttt{'stablehlo.broadcast\_in\_dim' op attribute 'broadcast\_dimensions' failed to satisfy constraint: i64 dense array attribute}\\[2pt]
\textbf{Repair} (accepted by verifier and oracle):\\
\texttt{\%0 = "stablehlo.broadcast\_in\_dim"(\%b) \{broadcast\_dimensions = \textbf{array<i64: 0>}\} \ldots}
