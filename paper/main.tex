\title{What Makes a Virtual ISA Programmable by AI Agents?\\
A Controlled Study of Agent-Facing Interfaces to StableHLO}

\begin{abstract}
AI agents increasingly write code at the virtual instruction-set architecture (ISA) layer, while benchmarks score the agent rather than the \emph{interface} the ISA exposes to it. Isolating that interface is hard, because documentation variants must carry the same facts, examples and length, or the comparison measures something else. We fix one intermediate representation (IR), StableHLO, together with a pinned verifier and executor, the tasks and the agent loop, and vary only how semantic documentation reaches the agent: none, syntax only, natural-language prose, a structured JSON contract with the same canonical facts and code examples at matched length, and on-demand retrieval through a tool (free, forced, or with the cross-cutting rules given upfront). We ran a pre-registered study on 267 held-out tasks (114 synthetic, 153 lowered from KernelBench PyTorch modules) with independent oracles and three GPT-4.1 snapshots (5{,}005 trials). Documentation was the dominant lever, adding 16 to 33 percentage points (pp) of first-attempt correctness over none. Once representation confounds were removed, the structured contract scored below prose for every model in point estimate ($-6.0$, $-7.9$, $-12.1$\pp), significantly for the two larger models, reversing the trend of our own earlier, unmatched comparison. On-demand access trailed upfront delivery by 4--32\pp: the strongest model never called the tool unless forced, partial upfront documentation suppressed lookup, and retrieving agents often missed the cross-cutting encoding rule on which correctness hinged. Over 99\% of failures were rejected statically, even on real-world tasks, so for this model family agent-facing virtual-ISA design is first a problem of making well-formedness learnable. Harness, tasks, protocol and logs are released.
\end{abstract}

\section{Introduction}
A virtual ISA decouples programs from rapidly changing hardware: front ends target the virtual layer and back ends absorb the churn~\cite{lattner2004llvm,lattner2021mlir}. Increasingly, the producer at that layer is an AI agent that writes, repairs and lowers code, which makes the presentation of the ISA to a non-human programmer a design dimension in its own right. Existing benchmarks score models on GPU kernels~\cite{ouyang2025kernelbench,li2025tritonbench,guan2026tritongym}, LLVM IR optimization~\cite{yang2026cirbench} or unfamiliar accelerator ISAs~\cite{nie2026kernelcraft}; they answer ``how good is the agent?'' for a given interface. We ask the complementary question: \emph{for a fixed agent and a fixed IR, which properties of the agent-facing interface change whether the agent writes correct programs?}

Isolating the interface is harder than it looks, for three reasons. First, documentation variants must be information-equivalent: if one rendering carries a concrete example and another only a schema, or one is longer, the comparison measures that difference rather than the representation. Our own first study fell into this trap and reached a conclusion that later reversed (\S\ref{sec:results}). Second, correctness must be judged by oracles that are independent of the IR, including for real-world code lowered from ML frameworks. Third, making documentation available is not the same as having it used: an agent with a retrieval tool may never call it.

We address these challenges with a fact-level design on StableHLO~\cite{stablehlospec}, a versioned, specification-backed MLIR dialect~\cite{lattner2021mlir} that serves as a portability layer between ML frameworks and compilers (Fig.~\ref{fig:overview}). A canonical inventory anchored to the pinned specification is rendered as length-matched prose, as a formal contract with the same examples, or behind a retrieval tool whose uptake we measure and, in one condition, force. Correctness is judged by numpy or PyTorch oracles on held-out inputs. In our data the answer is dominated by \emph{well-formedness}: agents rarely wrote programs that verified but computed the wrong values. Our claims are therefore about making an ISA's surface and static rules learnable, not about semantic reasoning.

\textbf{Contributions.} (i)~A controlled methodology and harness that vary agent-facing ISA documentation while holding IR, toolchain, tasks and agent loop fixed, with an automated equivalence audit (\S\ref{sec:design}). (ii)~A 328-task StableHLO suite: synthetic tasks plus 176 KernelBench modules lowered and validated end-to-end against PyTorch oracles (\S\ref{sec:tasks}). (iii)~Two studies: an exploratory one that exposed confounds in our own treatments, and a pre-registered one (5{,}005 trials) that removes them (\S\ref{sec:results}). (iv)~Design implications for agent-facing virtual ISAs, including results that reverse the ones we obtained before matching the treatments (\S\ref{sec:implications}).

\section{Related Work}
Kernel and IR benchmarks fix the interface and compare agents. KernelBench~\cite{ouyang2025kernelbench} and TritonBench~\cite{li2025tritonbench} evaluated LLM generation of efficient GPU kernels from PyTorch-level references, and TritonGym~\cite{guan2026tritongym} added agentic tool use to separate model ability from workflow design. CIRBench~\cite{yang2026cirbench} evaluated LLMs on analyzing, repairing and optimizing LLVM IR, and KernelCraft~\cite{nie2026kernelcraft} benchmarked agents writing kernels for emerging accelerator ISAs. Schema-derived constrained decoding addressed natural-language-to-MLIR generation, including StableHLO, from the decoder side~\cite{rath2026mlirdecoding}, which is complementary to changing the interface.

Interface and documentation studies vary what the model sees. SWE-agent~\cite{yang2024sweagent} showed that the design of the \emph{agent-computer interface} changes agent success; its interface is a set of tools and actions, whereas ours is the ISA's documentation. DocPrompting~\cite{zhou2023docprompting} showed that retrieved documentation helps code generation for unseen APIs. For PDDL, a low-resource planning language, documentation alone did not help, but pipeline-driven retrieval combined with modular generation and error refinement did~\cite{wang2025pddldocs}; in our study the \emph{agent} drives retrieval, and the outcome hinges on uptake and on which facts it requests. Code models carry stale knowledge of evolving APIs~\cite{ashik2026evolvingapis}, the mechanism behind the legacy attribute encodings that StableHLO's verifier rejects in our logs. Prompt-format studies showed that semantically equivalent formatting changes can swing LLM accuracy widely, with weak correlation across models~\cite{sclar2024format}, and that plain-text, Markdown, JSON and YAML templates change GPT-model results, with larger models more robust~\cite{he2024promptformat}. Our F2 is consistent with format sensitivity, but in our data the format penalty did not shrink with model size. We bring this interface view to the virtual ISA and manipulate the representation and access mode of its documentation at the level of fact-equivalent treatments.

\textbf{F1: Documentation was the dominant lever.} Syntax facts alone (A$-$None) added $+15.7$, $+32.6$ and $+27.5$\pp{} (all Holm $p<0.001$). Without documentation, mini solved 1 of 267 tasks. Semantic and shape facts on top of syntax (B$-$A) added $+4.5$ (n.s.), $+8.2$ and $+14.3$\pp, growing with capability.

\textbf{F2: With matched content, the structured contract scored below prose.} The primary contrast C$-$B was negative for every model: $-6.0$\pp{} [$-12.5$, $0.0$] for nano (Holm $p=0.083$, n.s.), $-7.9$\pp{} [$-12.6$, $-3.7$] for mini ($p<0.001$) and $-12.1$\pp{} [$-19.1$, $-5.7$] for 4.1 ($p=0.004$, 11 vs.\ 0 discordant tasks). Where the penalty fell depended on the model. For 4.1 it was concentrated on KernelBench (30.8\% with prose vs.\ 11.5\% with the contract, $-19.2$\pp, $p=0.016$ with Holm correction within the suite), while on synthetic tasks the two were within 3\pp{} (89.7\% vs.\ 87.2\%). For nano and mini it was instead larger on synthetic tasks ($-13.2$ and $-11.4$\pp) than on KernelBench ($-0.7$ and $-5.2$\pp), where their accuracy was low overall. The format of syntax facts alone made no difference (N$-$A: $-3.4$, $-0.4$, $-2.2$\pp, all n.s.). The penalty is therefore consistent with expressing semantic and shape constraints as formal predicates, but C also differs from B in its JSON wrapper, fact IDs and grouping by category; separating these would need an ablation with prose sentences inside JSON. For 4.1 the extra structured failures were mostly shape/type verifier errors (32 vs.\ 13 first attempts), and for mini mostly assembly and attribute errors (62 vs.\ 35).

\textbf{Confound check.} Matching instances and length changed the conclusions of Study~1 (Table~\ref{tab:confound}, identical synthetic tasks). Nano's penalty shrank from $-39.5$ to $-13.2$\pp, so most of the Study~1 collapse was an inability to instantiate abstract schemas. Mini's prose advantage was unchanged ($-13.2$ vs.\ $-11.4$\pp), so a format effect remains. For 4.1, the effect moved from $+2.6$ to $-2.6$\pp{} (both n.s.), so Study~1's ``structure helps the strongest model'' did not survive. The comparison is between studies rather than randomized within one, and the inventory also gained one reduce fact and a longer encoding rule. Even so, it shows that unmatched documentation comparisons can mislead.

\textbf{F3: On-demand access trailed upfront delivery.} D$-$C was $-4.1$ (n.s.), $-13.5$ and $-31.9$\pp, for three reasons. \emph{Uptake:} 4.1 never called the retrieval tool (0 of 91 tasks), replicating Study~1, while nano and mini averaged 1.3 and 2.4 calls. \emph{Forcing helped only the model that would not ask:} requiring a first-turn call (D$^\ast$) lifted 4.1 by $+17.6$\pp{} ($p=0.007$; Study~1 post-hoc: $+21.1$), but left mini and nano unchanged and still trailed C by 14\pp. \emph{Partial documentation suppressed lookup:} giving the cross-cutting rules upfront (D$^+$) helped 4.1 ($+17.6$\pp{} over D, $p<0.001$), but nano then almost stopped retrieving (0.02 calls per trial, down from 1.34) and lost $-9.0$\pp{} ($p<0.001$). For every model, D$^+$ remained 13--14\pp{} below C.

Which facts were fetched decided the outcome. When a retrieving agent fetched the cross-cutting \texttt{module} facts, which include the attribute-encoding rule, it was correct 62\% (nano), 51\% (mini) and 57\% (4.1, forced) of the time; when it did not, 7\%, 2\% and 16\%. Without that rule, 44\% of forced 4.1 attempts failed on attribute encoding, and only 24--52\% of retrieving trials requested it. This is observational, because agents chose what to fetch, but it replicates Study~1 (88\% vs.\ 22\%). Together with D$^+$, it suggests that agents need both the cross-cutting rules and the operation facts, and that, left to choose, they often fail to fetch the cross-cutting rule. On-demand access was not cheaper either: forced retrieval used 7\% \emph{more} input tokens per trial than C for 4.1 (7.4k vs.\ 6.9k), with 14\pp{} lower accuracy.

\textbf{F4: Agents failed at well-formedness, not numerics.} Across models, 99.2--99.8\% of failed first attempts were rejected by the parser, the verifier or the signature check. This held on the KernelBench suite too: at most 0.5\% of its failed first attempts verified and then produced wrong values, so harder, real-world tasks lowered correctness without making semantics the bottleneck. Only 15 of the 5{,}000 analyzed first attempts executed and produced wrong values. The failure mix was dominated by invalid assembly syntax (33--44\%), shape/type verifier errors (14--27\%), malformed literals (16--22\%) and attribute encoding (13--16\%). Fig.~\ref{fig:overview} (right) shows a typical case: under D$^+$, mini had the encoding rule upfront, still wrote the legacy \texttt{dense} form, and repaired it after the verifier diagnostic. Up to two repairs added 0.3--14.2\pp, with the largest gain for mini under D$^+$.

\section{Implications for Agent-Facing Virtual ISAs}\label{sec:implications}
The following are hypotheses supported for one model family and one IR, stated as design guidance to be re-tested on others.
\textbf{Validate interface claims with matched treatments.} The same comparison gave opposite answers before and after we equalized content, examples and length, so agent-facing ISA documentation should be evaluated with fact-equivalent, length-matched variants.
\textbf{Prefer explained constraints to bare predicates.} A machine-readable contract is useful for tools, but prose scored at or above the contract for every model. An ISA can ship both, generated from one fact inventory, and give agents the prose.
\textbf{Do not rely on agents to ask.} Strong agents skipped retrieval, partially documented agents stopped retrieving, and retrieving agents often missed the cross-cutting rule. Introspection APIs therefore need uptake design, such as a required first query or diagnostics that cite the violated fact. Returning cross-cutting rules with every operation-level answer is a further option that F3 motivates but we did not test.
\textbf{Make well-formedness learnable.} Most failures are static, so a normative, version-pinned surface syntax with concrete instances, plus diagnostics that name the violated rule, targets the actual bottleneck.

\section{Threats to Validity}
\emph{Models.} We used three snapshots of one family (GPT-4.1, April 2025) at temperature~0, with one trial per cell. Behaviors such as never calling a tool may be habits of this family, so every implication is a hypothesis for other families. Model 4.1 covers 91 of 267 tasks because of the budget cap, so its estimates have wider intervals.
\emph{Tasks.} Synthetic tasks are small and fully specified, and KernelBench tasks were shrunk and exclude large 3D transposed convolutions. KernelBench oracle cases inherit its non-negative input distribution, which missed mutants in 9 tasks (\S\ref{sec:tasks}). Because almost all failures are static, these results speak to syntactic and structural programmability more than to semantic reasoning.
\emph{Treatments.} The fact inventory and audit were authored by the study team with AI assistance; the audit is necessary but not sufficient, and an independent human audit is pending. Prose and contract differ in notation by design (sentences vs.\ predicates), and our claim concerns that difference at matched content and length.
\emph{Agent loop.} Repairs are harness-driven. We implemented a closed-loop agent track (self-directed verify, run-example and submit tools) but did not run it within this budget, so we make no claims about fully autonomous agents.
\emph{Procedure.} Two robustness fixes during Study~2 (API key precedence, and a call watchdog after network stalls) changed no prompt, grading or analysis; both are recorded as dated addenda.

\section{Conclusion}
We have shown that, holding the IR, toolchain, tasks and agent fixed, the agent-facing interface of a virtual ISA changed correctness by tens of percentage points. Documentation presence dominated; at matched content, prose scored at or above a formal contract; and on-demand access failed unless uptake was designed in. We have also shown that unmatched documentation comparisons can reverse these conclusions. Agent-facing virtual ISAs should therefore be engineered and measured as interfaces, with matched controlled experiments, and our next step is to test these hypotheses on other model families and on a closed-loop agent.
