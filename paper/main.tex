\title{What Makes a Virtual ISA Programmable by AI Agents?\\
A Controlled Study of Agent-Facing Interfaces to StableHLO}

\begin{abstract}
AI agents increasingly write code at the virtual-ISA layer, yet benchmarks score the agent, not the \emph{interface} the ISA exposes to it. We fix one IR (StableHLO), one pinned verifier and executor, the tasks and the agent loop, and vary only how semantic documentation reaches the agent: none, syntax only, natural-language prose, a structured JSON contract with the same canonical facts and the same code examples at matched length, and on-demand retrieval through a tool (free, forced, or with the cross-cutting rules given upfront). A pre-registered study on 267 held-out tasks (114 synthetic, 153 lowered from KernelBench PyTorch modules) with independent oracles and three GPT-4.1 snapshots (5{,}005 trials) finds that: (1)~documentation is the dominant lever ($+16$ to $+33$\pp{} first-attempt correctness over none); (2)~once representation confounds are removed, prose beats the structured contract for every model ($-6.0$, $-7.9$, $-12.1$\pp), most strongly on real-world tasks, overturning the opposite trend in our own earlier unmatched comparison; and (3)~on-demand access underperforms upfront delivery by 4--32\pp: the strongest model never calls the tool unless forced, partial upfront documentation suppresses lookup, and agents that do retrieve seldom fetch the cross-cutting encoding rule on which correctness hinges. Over 99\% of failures are rejected statically, even on real-world tasks, so for this model family agent-facing VISA design is first a problem of making well-formedness learnable. Harness, tasks, protocol and logs are released.
\end{abstract}

\section{Introduction}
A virtual ISA decouples programs from rapidly changing hardware: front ends target the virtual layer and back ends absorb the churn~\cite{lattner2004llvm,lattner2021mlir}. Increasingly the producer at that layer is an AI agent that writes, repairs and lowers code. This makes the presentation of the ISA to a non-human programmer a design dimension in its own right. Benchmarks score models on GPU kernels~\cite{ouyang2025kernelbench,li2025tritonbench,guan2026tritongym}, LLVM IR optimization~\cite{yang2026cirbench} or unfamiliar accelerator ISAs~\cite{nie2026kernelcraft}; they answer ``how good is the agent?'' for a given interface. We ask the complementary question: \emph{for a fixed agent and a fixed IR, which properties of the agent-facing interface change whether the agent writes correct programs?} In our data the answer is dominated by \emph{well-formedness}: agents rarely write programs that verify but compute the wrong values. Our claims are therefore about making an ISA's surface and static rules learnable, not about semantic reasoning.

We study StableHLO~\cite{stablehlospec}, a versioned, specification-backed MLIR dialect~\cite{lattner2021mlir} that serves as a portability layer between ML frameworks and compilers. The manipulation is controlled at the level of individual facts: a canonical inventory anchored to the pinned specification is rendered as prose, as a formal contract, or behind a retrieval tool.

\textbf{Contributions.} (i)~A controlled methodology and harness that vary agent-facing ISA documentation while holding IR, toolchain, tasks and agent loop fixed, with an automated equivalence audit. (ii)~A 328-task StableHLO suite: synthetic tasks plus 176 KernelBench modules lowered and validated end-to-end against PyTorch oracles. (iii)~Two studies: an exploratory one that exposed confounds in our own treatments, and a pre-registered one (5{,}005 trials) that removes them. (iv)~Design implications for agent-facing virtual ISAs, including results that reverse the ones we obtained before matching the treatments.

\section{Related Work}
KernelBench~\cite{ouyang2025kernelbench} and TritonBench~\cite{li2025tritonbench} evaluate LLM generation of efficient GPU kernels from PyTorch-level references. TritonGym~\cite{guan2026tritongym} adds agentic tool use to separate model ability from workflow design. CIRBench~\cite{yang2026cirbench} evaluates LLMs on analyzing, repairing and optimizing LLVM IR, and KernelCraft~\cite{nie2026kernelcraft} benchmarks agents writing kernels for emerging accelerator ISAs. SWE-agent~\cite{yang2024sweagent} shows that the design of the \emph{agent-computer interface} changes agent success; its interface is a set of tools and actions, whereas ours is the ISA's documentation. DocPrompting~\cite{zhou2023docprompting} shows that retrieved documentation helps code generation for unseen APIs. For PDDL, a low-resource planning language, documentation alone did not help, but pipeline-driven retrieval combined with modular generation and error refinement did~\cite{wang2025pddldocs}. In our study the \emph{agent} drives retrieval, and the outcome hinges on uptake and on which facts the agent requests. Code models carry stale knowledge of evolving APIs~\cite{ashik2026evolvingapis}; we see the same mechanism in the legacy attribute encodings StableHLO's verifier rejects. Schema-derived constrained decoding attacks NL-to-MLIR generation, including StableHLO, from the decoder side~\cite{rath2026mlirdecoding}, which is complementary to changing the interface. We bring the interface view to the virtual ISA. We hold model, IR and tasks fixed, and manipulate the representation and access mode of the ISA's semantic documentation at the level of fact-equivalent treatments.

\textbf{F1: Documentation is the dominant lever.} Syntax facts alone (A$-$None) add $+15.7$, $+32.6$ and $+27.5$\pp{} (all Holm $p<0.001$). Without documentation gpt-4.1-mini solves 1 of 267 tasks. Semantic and shape facts on top of syntax (B$-$A) add $+4.5$ (n.s.), $+8.2$ and $+14.3$\pp, growing with capability.

\textbf{F2: With matched content, prose beats the structured contract.} The primary contrast C$-$B is negative for every model: $-6.0$\pp{} [$-12.5$, $0.0$] for nano (Holm $p=0.083$), $-7.9$\pp{} [$-12.6$, $-3.7$] for mini ($p<0.001$) and $-12.1$\pp{} [$-19.1$, $-5.7$] for gpt-4.1 ($p=0.004$, 11 vs.\ 0 discordant tasks). The effect is concentrated on real-world tasks: on KernelBench, gpt-4.1 solves 30.8\% with prose and 11.5\% with the contract ($-19.2$\pp, $p=0.016$), while on synthetic tasks the two are within 3\pp{} (89.7\% vs.\ 87.2\%), reproducing our exploratory Study~1 numbers on the same tasks (88.6\% vs.\ 91.2\%). The format of syntax facts alone does not matter (N$-$A: $-3.4$, $-0.4$, $-2.2$\pp, all n.s.). The penalty therefore comes from expressing semantic and shape constraints as formal predicates. For gpt-4.1 the extra structured failures are mostly shape/type verifier errors (32 vs.\ 13 first attempts), and for mini mostly assembly and attribute errors (62 vs.\ 35). \emph{Confound check.} Table~\ref{tab:confound} compares the two studies on the identical 114 synthetic tasks. Matching instances and length shrank the smallest model's penalty from $-39.5$ to $-13.2$\pp; most of the Study~1 collapse was an inability to instantiate abstract schemas. Mini's prose advantage was unchanged ($-13.2$ vs.\ $-11.4$\pp), so a genuine format effect remains. gpt-4.1's effect moved from $+2.6$ to $-2.6$\pp{} (both n.s.), so Study~1's ``structure helps the strongest model'' did not survive. The comparison is between studies, not randomized within one, and the inventory also gained one reduce fact and a longer encoding rule. Even so, it shows that unmatched documentation comparisons can mislead.

\textbf{F3: On-demand access underperforms upfront delivery, for three reasons.} D$-$C is $-4.1$ (n.s.), $-13.5$ and $-31.9$\pp. \emph{Uptake:} gpt-4.1 never called the retrieval tool (0 of 91 tasks), replicating Study~1, while nano and mini averaged 1.3 and 2.4 calls. \emph{Forcing helps only the model that would not ask:} requiring a first-turn call (D$^\ast$) lifts gpt-4.1 by $+17.6$\pp{} ($p=0.007$; Study~1 post-hoc: $+21.1$) but leaves mini and nano unchanged, and still trails C by 14\pp. \emph{Partial documentation suppresses lookup:} giving the cross-cutting rules upfront (D$^+$) helps gpt-4.1 ($+17.6$\pp{} over D, $p<0.001$), but nano then almost stops retrieving (0.02 calls per trial, down from 1.34) and loses $-9.0$\pp{} ($p<0.001$). For every model D$^+$ remains 13--14\pp{} below C. \emph{Which facts are fetched decides the outcome.} When a retrieving agent fetched the cross-cutting \texttt{module} facts, which include the attribute-encoding rule, it was correct 62\% (nano), 51\% (mini) and 57\% (gpt-4.1, forced) of the time; when it did not, 7\%, 2\% and 16\%. Without that rule, 44\% of forced gpt-4.1 attempts failed on attribute encoding. Only 24--52\% of retrieving trials requested it. This is observational, because agents choose what to fetch, but it replicates Study~1 (88\% vs.\ 22\%). Together with D$^+$, it suggests that agents need both the cross-cutting rules and the operation facts, and on their own fetch at most one of them. On-demand access is not cheaper either: forced retrieval used 7\% \emph{more} input tokens per trial than C for gpt-4.1 (7.4k vs.\ 6.9k), with 14\pp{} lower accuracy.

\textbf{F4: Agents fail at well-formedness, not numerics.} Across models, 99.2--99.8\% of failed first attempts were rejected by the parser, the verifier or the signature check. This holds on the KernelBench suite too: at most 0.5\% of its failed first attempts verified and then produced wrong values. Harder, real-world tasks lowered correctness without making semantics the bottleneck. Only 15 of the 5{,}000 analysed first attempts executed and produced wrong values. The failure mix is dominated by invalid assembly syntax (33--44\%), shape/type verifier errors (14--27\%), malformed literals (16--22\%) and attribute encoding (13--16\%). Up to two repairs add 0.3--14.2\pp, with the largest gain for mini under D$^+$.

\section{Implications for Agent-Facing VISAs}\label{sec:implications}
These are hypotheses supported for one model family and one IR, stated as design guidance to be re-tested on others.
\textbf{Validate interface claims with matched treatments.} The same comparison gave opposite answers before and after we equalized content, examples and length. Agent-facing ISA documentation should be evaluated with fact-equivalent, length-matched variants.
\textbf{Prefer explained constraints to bare predicates.} A machine-readable contract is useful for tools, but agents applied shape constraints better when they were stated in prose. An ISA can ship both, generated from one fact inventory, and give agents the prose.
\textbf{Do not rely on agents to ask.} Strong agents skipped retrieval, partially documented agents stopped retrieving, and retrieving agents missed the cross-cutting rule. Introspection APIs need uptake design, such as a required first query or diagnostics that cite the violated fact. Cross-cutting rules should also accompany every operation-level answer, rather than being delivered once upfront.
\textbf{Make well-formedness learnable.} Most failures are static. A normative, version-pinned surface syntax with concrete instances, plus diagnostics that name the violated rule, targets the actual bottleneck.

\section{Threats to Validity}
\emph{Models:} three snapshots of one family (GPT-4.1, April 2025) at temperature~0, one trial per cell. Behaviours such as never calling a tool may be habits of this family, so every implication is a hypothesis for other families. gpt-4.1 covers 91 of 267 tasks because of the budget cap, so its estimates have wider intervals. \emph{Tasks:} synthetic tasks are small and fully specified, and KernelBench tasks were shrunk and exclude large 3D transposed convolutions. Because almost all failures are static, these results speak to syntactic and structural programmability more than to semantic reasoning. \emph{Treatments:} the fact inventory and audit were authored by the study team with AI assistance; the audit is necessary but not sufficient, and an independent human audit is pending. Prose and contract differ in notation by design (sentences vs.\ predicates); our claim concerns that difference at matched content and length. \emph{Agent loop:} repairs are harness-driven. We implemented a closed-loop agent track (self-directed verify, run-example and submit tools) but did not run it within this budget, so we make no claims about fully autonomous agents. \emph{Procedure:} two robustness fixes during Study~2 (API key precedence, a call watchdog after network stalls) changed no prompt, grading or analysis. Both are recorded as dated addenda.

\section{Conclusion}
Holding the IR, toolchain, tasks and agent fixed, the agent-facing interface of a virtual ISA changes correctness by tens of percentage points. Documentation presence dominates. At matched content, prose beats a formal contract, most strongly on real-world lowering tasks. On-demand access fails unless uptake is designed in. Agent-facing VISAs should be engineered and measured as interfaces, with matched controlled experiments.
